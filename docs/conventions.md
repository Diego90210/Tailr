# Code Conventions

> Extreme consistency. AI performs better when the repository looks like itself everywhere.

## TypeScript / React Style

* **Formatting:** 2-space indent, double quotes, semicolons.
* **Components:** Function components only. `"use client"` at the top only when hooks or browser APIs are used.
* **Imports:** React/Next first, then third-party, then local via the `@/` alias.
* **Styling:** Tailwind utility classes inline. No CSS modules, no styled-components.
* **Data fetching:** React Server Components by default. Client components only for interactive surfaces (chat, forms, uploads).
* **Validation:** every external boundary (route handler input, LLM output, form payload) is parsed with a zod schema from `lib/contracts/`. Never trust a raw object.

## Python Style (docgen service)

* **Version:** Python 3.11.
* **Formatting:** PEP 8. Maximum line length of 100 characters.
* **Imports:** stdlib first, then third-party, then local. One module per line.
* **Strings:** Always use double quotes `"..."`. Single quotes only to escape double quotes inside strings.
* **f-strings:** Use f-strings for interpolation. No `.format()` or `%`.
* **Scope:** `services/docgen/` renders documents and measures pagination. It contains **no** business logic, no LLM calls and no database access.

## File Structure

Every Python file in `services/docgen/` starts with:

```python
"""One-line description of the module's purpose."""

# stdlib imports
from dataclasses import dataclass

# third-party imports
from docx import Document
from PIL import ImageFont

# local imports
from measure import count_wrapped_lines
```

Every React component file:

```tsx
"use client"; // only if hooks/browser APIs are used

export default function ComponentName() {
  return ( ... );
}
```

## LLM Layer

* **Single entry point:** everything goes through `lib/llm/index.ts`. No SDK import outside `lib/llm/providers/`.
* **Routing by task:** the model for each `TaskKind` comes from environment variables (`LLM_ROUTE_*`). Changing a model must never require a code change.
* **Structured output:** every prompt that returns data declares a zod schema; the response is parsed before use and a parse failure is an error, not a fallback to prose.
* **Structured failure:** if all providers fail, return a typed error. Never silently degrade to a different provider that does not meet the zero-retention bar.
* **Metering:** every call writes one `usage_events` row (provider, model, tokens in/out, estimated cost, latency). No exceptions.
* **Prompts:** all prompt text lives in `prompts/*.md`. No prompt string literals in source files.
* **Untrusted content:** posting and CV text are wrapped in explicit delimiters and labelled as data in the system prompt.

## Fact-Locking

* A generated bullet carries `factIds: string[]` with at least one entry.
* The validator rejects: empty `factIds`, unknown IDs, bullets over 220 characters, and any number in the bullet text that does not appear in the referenced facts.
* A rejected bullet is **dropped and logged**. Never repaired silently, never shipped.
* The humanizer pass runs **before** the final numeric validation, because rewriting can introduce numbers.

## Database

* All tables have RLS enabled. Ownership resolves from `auth.jwt()->>'sub'` (the Clerk subject).
* The frontend never writes directly: mutations go through route handlers that perform an explicit ownership check in addition to RLS.
* UUIDs are generated by Postgres (`gen_random_uuid()`), not by application code.
* Migrations are append-only files in `supabase/migrations/`. Never edit a merged migration.
* Secrets (`SUPABASE_SERVICE_ROLE_KEY`, provider keys, `BYO_KEY_ENCRYPTION_KEY`) exist only server-side. Only `NEXT_PUBLIC_*` variables reach the browser.

## Internationalization

* Languages: `es` (default) and `en`.
* No hardcoded user-facing string in a component; everything comes from `messages/*.json`.
* Two independent axes: **UI language** (user preference) and **CV language** (from the posting). Do not couple them.
* Any string added in one language must be added in the other in the same change, or the build fails.

## Error Handling

Python (docgen) raises named exceptions:

```python
class DocgenError(Exception):
    """Base class for document generation errors."""


class CannotFitOnePage(DocgenError):
    """Raised when the pagination loop cannot converge to a single page."""
```

TypeScript failures use typed results at the boundary:

```ts
type Result<T, E> = { ok: true; data: T } | { ok: false; error: E };
```

API errors use the envelope `{ error: { code, message, details } }` with a **localized** `message`. React pages always have a matching `error.tsx` and `loading.tsx`; error pages use `reset()` to retry. Never `alert()`.

## Tests

* One test file per module: `lib/<area>/<module>.test.ts` or `services/docgen/tests/test_<module>.py`.
* One `test_*` function per acceptance criterion.
* Use `tempfile.TemporaryDirectory()` for any file I/O and clean up.
* Descriptive names: `test_validator_rejects_number_absent_from_facts`.
* Tests are pure: no network calls to Supabase, Clerk, Upstash or an LLM provider. Use the mock provider from `LLM-09`.
* Frontend gates: `pnpm lint`, `pnpm build`, `pnpm test`, `pnpm test:i18n`.

## Comments

By default, **do not** write comments. They are only allowed when they explain a non-obvious *why* (a documented workaround, a subtle invariant such as the double numeric check after the humanizer pass). Names should communicate everything else.

## Security

* Treat every byte that comes from a user as hostile: the posting, the CV text, chat messages and file names.
* Never log or emit content. Log identifiers, sizes, token counts and timings.
* Short-lived signed URLs (15 minutes) for generated documents; never a public bucket path.
* BYO keys are write-only from the client's perspective: return `provider` and `key_hint`, never the key.
